# Issue 213 Exposed Gradle Plugin

## Context

Issue #213 asked the repository to adopt JetBrains' official Exposed Gradle
plugin and document plugin usage for downstream repositories.

## Decision

Consume `org.jetbrains.exposed.plugin` from the central `bt4k` version catalog
using the shared JetBrains Exposed version line, expose it from the root build
with `apply false`, and apply/configure it only in demo application modules with
concrete table packages and H2 migration targets.

## Outcome

The JDBC and R2DBC demo modules now expose executable `generateMigrations` tasks
and include deterministic initial migration scripts generated by the plugin.
Root README files document the plugin and link to JetBrains documentation plus
the Gradle Plugin Portal.

## Verification

- `./gradlew help --configuration-cache`
- `./gradlew :exposed-spring-boot-jdbc-demo:generateMigrations --filename=V1__create_products.sql --configuration-cache`
- `./gradlew :exposed-spring-boot-r2dbc-demo:generateMigrations --filename=V1__create_webflux_products.sql --configuration-cache`
- `./gradlew :exposed-spring-boot-jdbc-demo:test :exposed-spring-boot-r2dbc-demo:test --configuration-cache`

## Future Guard

Do not apply the Exposed Gradle plugin to library modules unless a concrete
`exposed.migrations` configuration exists. Otherwise the task is visible but
not useful for migration generation.
