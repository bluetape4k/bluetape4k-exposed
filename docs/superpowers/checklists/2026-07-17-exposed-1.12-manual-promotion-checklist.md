# Exposed 1.12 매뉴얼 승격 체크리스트

상태: 릴리스 마무리 대기

소유자: bluetape4k-exposed 1.12.0용
`bluetape-publish-jvm` 릴리스/퍼블리시 워크플로

이 추적 문서는 현재 `README.md` 및 `README.ko.md`의 develop 마이그레이션
가이드를 안정화된 이중 언어 매뉴얼로 이후 승격하는 작업을 관리합니다. Issue #322는
`docs/manual/**`을 변경하지 않습니다. 정확한 1.12.0 릴리스 ref와 커밋이 존재할 때까지
해당 파일은 1.11.0에 계속 고정됩니다.

## 릴리스 권한

- [ ] **REL-01 — 변경 불가능한 릴리스 소스 고정**
  - **작업:** 정확한 1.12.0 tag/ref와 전체 릴리스 커밋을 기록합니다.
  - **증거:** Live tag 해석, 로컬 객체 식별자, 릴리스 체크리스트 대상이 모두
    동일한 커밋을 지정합니다.
  - **실패:** `develop`, 이동하는 브랜치 또는 검증되지 않은 tag에서 안정화된
    매뉴얼을 편집하지 않습니다.
- [ ] **REL-02 — 퍼블리시된 동작 확인**
  - **작업:** 가이드를 승격하기 전에 정확한 릴리스 트리에 문서화된
    Exposed Gradle plugin 통합, JDBC/R2DBC `migrationDriftTest` tasks 및
    마이그레이션 워크플로가 포함되어 있는지 검증합니다.
  - **증거:** 정확한 ref의 소스 경로, task 목록 및 릴리스 검증 결과입니다.
  - **실패:** 매뉴얼 승격 전에 현재 develop에만 해당하는 주장을 제거하거나
    조건을 명시합니다.

## 이중 언어 승격

- [ ] **MAN-01 — 정확한 릴리스 인벤토리 내보내기**
  - **작업:** 고정된 릴리스 커밋에서 1.12.0 모듈 인벤토리를 내보냅니다.
  - **증거:** 정확한 릴리스 커밋에서 생성된
    `build/manual/module-inventory-1.12.0.json`입니다.
  - **실패:** 인벤토리 생성이 다른 ref에서 수행되거나 해결되지 않은 모듈 drift를
    남기는 경우 중단합니다.
- [ ] **MAN-02 — 두 로케일을 함께 승격**
  - **작업:** 애플리케이션 사용자와 저장소 기여자를 위한 동등한 영어 및 한국어
    안정화 매뉴얼 가이드를 추가합니다. 여기에는 plugin/API 경계, 변경 불가능한
    파일명, 지원 제한, 진단, 스키마/데이터/롤아웃 검토가 포함됩니다.
  - **증거:** 일치하는 영어/한국어 경로, headings, commands, warnings,
    matrices 및 정확한 릴리스 소스 링크입니다.
  - **실패:** 로케일이 누락되거나 의미가 달라진 경우 승격을 차단합니다.
- [ ] **MAN-03 — 안정화 메타데이터 업데이트**
  - **작업:** `docs/manual/manifest.yaml`을 정확한 1.12.0 릴리스 ref, commit,
    inventory, documents, chapters 및 assets로 업데이트합니다.
  - **증거:** Manifest diff가 내보낸 inventory와 일치하고 추가된 모든 route 또는
    asset이 필요한 경우 두 로케일 모두에 존재합니다.
  - **실패:** 오래된 1.11.0 metadata, 이동하는 refs, 고아 파일 또는 등록되지 않은
    assets를 거부합니다.
- [ ] **MAN-04 — 소비자 버전 권한 유지**
  - **작업:** 예제는 `bluetape4k-dependencies` platform을 사용하고 개별
    bluetape4k library versions는 생략합니다.
  - **증거:** 안정화 매뉴얼의 dependency examples가 central BOM
    소유권을 유지합니다.
  - **실패:** 중복된 project 또는 library version declarations를 제거합니다.
## 릴리스 검증

- [ ] **VER-01 — 현재 README 패리티 검증**
  - **작업:** 지침을 복사하거나 조정하기 전에 포커스된 마이그레이션 README 검증기를 실행한다.
  - **증거:**
    `ruby scripts/manual/validate_migration_readme_parity.rb README.md README.ko.md`
    가 `Migration README parity is aligned`를 보고한다.
  - **실패 시:** 안정 릴리스 승격 전에 현재 문서의 불일치를 수정한다.
- [ ] **VER-02 — 매니페스트 및 로케일 계약 검증**
  - **작업:** 1.12.0 export를 대상으로 매뉴얼 계약 스위트와 인벤토리 검증기를 실행한다.
  - **증거:** Ruby 계약 스위트가 통과하고
    `ruby scripts/manual/validate_manuals.rb build/manual/module-inventory-1.12.0.json docs/manual/manifest.yaml`
    가 매뉴얼이 일치함을 보고한다.
  - **실패 시:** 릴리스 마무리 전에 누락된 모듈, 로케일 불일치, 링크, frontmatter,
    챕터 또는 에셋을 수정한다.
- [ ] **VER-03 — 정확한 릴리스 링크 및 주장 검증**
  - **작업:**
    `ruby scripts/manual/validate_release_manuals.rb 1.12.0 <release-commit>`
    를 실행하고, 새 마이그레이션 소스 링크를 pinned tree와 대조하여 모두 검사한다.
  - **증거:** 누락된 링크가 없고 안정 릴리스 페이지의 어떤 source URL도
    `develop`을 가리키지 않는다.
  - **실패 시:** 누락되었거나 변경될 수 있거나 develop 전용인 참조를 정확한
    릴리스 파일로 교체하거나 지원되지 않는 주장을 제거한다.
- [ ] **VER-04 — 결정적 출력 및 diff 위생 점검**
  - **작업:** 생성된 메타데이터를 두 번 다시 export하고 해시를 비교하며,
    `git diff --check`를 실행하고, 승격 diff에 의도한 매뉴얼, 매니페스트 및
    등록된 에셋 변경만 포함되어 있는지 확인한다.
  - **증거:** 동일한 export, 공백 오류 0건 및 검토된 파일 범위.
  - **실패 시:** publication 전에 비결정성, 잘못된 Markdown 또는 관련 없는 변경을 수정한다.

## 마무리

- [ ] **GH-01 — 릴리스 워크플로를 통해 검토 및 publish**
  - **작업:** 위 체크리스트의 모든 행이 통과한 후 publish workflow의 검토, 정확한 head CI,
    PR 및 merge gate를 완료한다.
  - **증거:** 해당 head에 연결된 정확한 PR head, 통과한 필수 검사, 검토 아티팩트 및
    merge 승인.
  - **실패 시:** 매뉴얼 승격을 pending 상태로 유지한다. issue #322 완료만으로는
    publication authority가 되지 않는다.
- [ ] **GH-02 — 안정 매뉴얼 provenance 기록**
  - **작업:** 최종 release ref, commit, 매뉴얼 인벤토리 수, 로케일 수, 검증 결과,
    PR 및 merge commit으로 이 tracker를 업데이트한다.
  - **증거:** 완료된 행에 재현 가능한 명령과 변경 불가능한 식별자가 포함된다.
  - **실패 시:** prose-only 확인만으로 승격 완료로 표시하지 않는다.
