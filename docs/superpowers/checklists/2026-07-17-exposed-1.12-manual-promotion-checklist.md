bluetape4k-exposed 1.12.0

This tracker owns the later promotion of current-develop migration guidance
from `README.md` and `README.ko.md` into the stable bilingual manual. Issue #322
does not change `docs/manual/**`: those files remain pinned to 1.11.0 until an
exact 1.12.0 release ref and commit exist.

## Release Authority

- [ ] **REL-01 — Pin the immutable release source**
  - **Action:** Record the exact 1.12.0 tag/ref and its full release commit.
  - **Evidence:** Live tag resolution, local object identity, and release
    checklist target all name the same commit.
  - **Failure:** Do not edit the stable manual from `develop`, a moving branch,
    or an unverified tag.
- [ ] **REL-02 — Confirm published behavior**
  - **Action:** Verify that the exact release tree contains the documented
    Exposed Gradle plugin integration, JDBC/R2DBC `migrationDriftTest` tasks,
    and migration workflows before promoting the guidance.
  - **Evidence:** Exact-ref source paths, task listing, and release validation.
  - **Failure:** Remove or qualify any current-develop-only claim before manual
    promotion.

## Bilingual Promotion

- [ ] **MAN-01 — Export the exact release inventory**
  - **Action:** Export the 1.12.0 module inventory from the pinned release
    commit.
  - **Evidence:** `build/manual/module-inventory-1.12.0.json` generated at the
    exact release commit.
  - **Failure:** Stop if inventory generation comes from another ref or leaves
    unresolved module drift.
- [ ] **MAN-02 — Promote both locales together**
  - **Action:** Add equivalent English and Korean stable-manual guidance for
    application users and repository contributors, including plugin/API
    boundaries, immutable filenames, support limits, diagnostics, and
    schema/data/rollout review.
  - **Evidence:** Matching English/Korean routes, headings, commands, warnings,
    matrices, and exact-release source links.
  - **Failure:** A missing or semantically drifted locale blocks promotion.
- [ ] **MAN-03 — Update stable metadata**
  - **Action:** Update `docs/manual/manifest.yaml` to the exact 1.12.0 release
    ref, commit, inventory, documents, chapters, and assets.
  - **Evidence:** Manifest diff matches the exported inventory and every added
    route or asset exists in both locales where required.
  - **Failure:** Reject stale 1.11.0 metadata, moving refs, orphan files, or
    unregistered assets.
- [ ] **MAN-04 — Preserve consumer version authority**
  - **Action:** Keep examples on the `bluetape4k-dependencies` platform and omit
    individual bluetape4k library versions.
  - **Evidence:** Stable manual dependency examples retain central BOM
    ownership.
  - **Failure:** Remove duplicated project or library version declarations.

## Release Validation

- [ ] **VER-01 — Validate current README parity**
  - **Action:** Run the focused migration README validator before copying or
    adapting the guidance.
  - **Evidence:**
    `ruby scripts/manual/validate_migration_readme_parity.rb README.md README.ko.md`
    reports `Migration README parity is aligned`.
  - **Failure:** Repair current-documentation drift before stable promotion.
- [ ] **VER-02 — Validate manifest and locale contracts**
  - **Action:** Run the manual contract suites and inventory validator against
    the 1.12.0 export.
  - **Evidence:** Ruby contract suites pass and
    `ruby scripts/manual/validate_manuals.rb build/manual/module-inventory-1.12.0.json docs/manual/manifest.yaml`
    reports aligned manuals.
  - **Failure:** Repair missing modules, locale drift, links, frontmatter,
    chapters, or assets before release closeout.
- [ ] **VER-03 — Validate exact-release links and claims**
  - **Action:** Run
    `ruby scripts/manual/validate_release_manuals.rb 1.12.0 <release-commit>`
    and inspect every new migration source link against the pinned tree.
  - **Evidence:** Zero missing links and no source URL points at `develop` from
    a stable release page.
  - **Failure:** Replace missing, moving, or develop-only references with exact
    release files or remove the unsupported claim.
- [ ] **VER-04 — Check deterministic output and diff hygiene**
  - **Action:** Re-export generated metadata twice, compare hashes, run
    `git diff --check`, and verify that the promotion diff contains only
    intended manual, manifest, and registered asset changes.
  - **Evidence:** Identical exports, zero whitespace errors, and reviewed file
    scope.
  - **Failure:** Fix nondeterminism, malformed Markdown, or unrelated changes
    before publication.
