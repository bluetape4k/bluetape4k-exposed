트랜잭션 경계 추적

Spring이 프록시를 통과하는 저장소 호출 주위에 JDBC 트랜잭션을 열고 저장소는 활성 컨텍스트에 참여합니다.

호출자저장소 메서드 하나를 호출합니다.
Spring 프록시@Transactional이 경계를 열거나 기존 경계에 참여합니다.
JDBC 저장소블로킹 Exposed 문장을 실행합니다.
Exposed 컨텍스트DAO 엔티티는 활성 트랜잭션이 필요합니다.
JDBC 드라이버설정된 DataSource를 사용합니다.
커밋Spring 소유 경계가 완료됩니다.

소유자: 이 저장소 호출을 감싸는 Spring JDBC 트랜잭션 인터셉터입니다.

코루틴 호출자중단 가능한 저장소 메서드를 호출합니다.
저장소비공개 inTransaction 도우미로 진입합니다.
suspendTransaction명시적인 Exposed R2DBC 경계를 엽니다.
Exposed 문장코루틴 트랜잭션 컨텍스트에서 실행됩니다.
R2DBC 드라이버애플리케이션이 제공한 데이터베이스를 사용합니다.
커밋저장소 소유 경계가 완료됩니다.

스트리밍 예외: streamAll은 channelFlow로 행을 전송하는 동안 suspendTransaction을 활성 상태로 유지합니다.

애플리케이션 서비스이체 같은 비즈니스 불변식을 소유합니다.
호출자 경계저장소 호출 전에 하나의 원자적 단위를 정의합니다.
저장소 A차감 또는 첫 번째 상태 변경입니다.
저장소 B입금 또는 두 번째 상태 변경입니다.
불변식 확인모든 문장이 성공하거나 작업 전체가 실패합니다.
커밋호출자가 소유하는 하나의 비즈니스 결과입니다.

원자성을 추정하지 마십시오. 각자 트랜잭션을 여는 여러 저장소 호출은 독립적으로 커밋될 수 있습니다. 선택한 JDBC 또는 R2DBC 스택에 맞춰 전파를 설계하고 검증해야 합니다.

호출자 소유 경계 JDBC / Spring R2DBC / 코루틴

모든 보기에서 유지되는 원칙

인프라 소유권을 드러냅니다

애플리케이션이 데이터베이스, 풀, 디스패처, 타임아웃, 종료 정책을 제공합니다. 중단 함수 API가 블로킹 JDBC 작업을 논블로킹으로 바꾸지는 않습니다.

취소 의미를 과장하지 않습니다

코루틴 취소만으로 롤백과 연결 반환이 이미 끝났다고 증명할 수 없습니다. 선택한 드라이버, 풀, Exposed, 프레임워크 조합을 검증하십시오.

트랜잭션 종속 값은 경계 안에서 소비합니다

JDBC DAO 엔티티와 지연 읽기는 활성 트랜잭션을 요구할 수 있습니다. 경계를 넘기기 전에 분리된 값으로 변환하십시오.

외부 I/O에 롤백을 약속하지 않습니다

HTTP 호출, 메시지, 파일은 데이터베이스 롤백으로 취소되지 않습니다. Outbox 같은 명시적인 전달 프로토콜을 사용하십시오.
