누가 계속 소유하는가?

Exposed JDBC와 R2DBC 통합에 영향을 주는 입력을 전환해 보십시오. 저장소 검색, 자동 구성 빈, Back-off, 애플리케이션이 제공해야 하는 인프라를 구분해 보여 줍니다.

추측이 아닌 조건 Back-off는 정상 상태 명시적인 애플리케이션 소유권

활성화 입력

JDBC와 R2DBC 저장소를 검색할 수 있습니다. JDBC 트랜잭션 매니저와 공유 매핑 컨텍스트가 자동 구성됩니다.

1 · 클래스패스 조건EntityClass가 있으므로 Exposed 자동 구성을 적용할 수 있습니다.
2 · JDBC 경로Registrar가 활성화되고 DataSource로 Exposed를 연결해 springTransactionManager를 만듭니다.
3 · R2DBC 경로Registrar만 활성화하며 R2DBC 풀, 데이터베이스, 트랜잭션 매니저는 만들지 않습니다.
4 · 공유 매핑자동 구성이 ExposedMappingContext를 만듭니다.
영역상태소유자
JDBC 저장소 검색활성활성화 애너테이션 + registrar
springTransactionManager생성JDBC 자동 구성
R2DBC 저장소 검색활성활성화 애너테이션 + registrar
ConnectionPool / R2dbcDatabase생성 안 함애플리케이션
ExposedMappingContext생성기존 빈이 없을 때 자동 구성

범위: 저장소 활성화를 집중해서 설명하는 자료이며 Spring Boot 전체 조건 평가 보고서를 모사하지 않습니다.
